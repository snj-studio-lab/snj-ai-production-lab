# CUT은 패널이 아니고, 패널은 영상 클립이 아니다

## 177개의 CUT이 있으면 177개의 영상 클립이 필요한가?

긴 AI 영상 제작 패키지를 처음 숫자로 검토하면 이런 질문이 자연스럽게 나온다.

```txt
CUT 177개
→ 이미지 177장?
→ 영상 생성 177회?
→ 최종 클립 177개?
```

답은 대체로 아니다.

문제는 177이라는 숫자가 크다는 데 있지 않다. 서로 다른 목적을 가진 제작 단위를 같은 것으로 취급하는 데 있다. `CUT`, 스토리보드 `PANEL`, 영상 생성용 `CLIP_GROUP`은 서로 연결되지만 같은 단위가 아니다.

이를 1:1로 환산하면 생성량만 늘어나는 것이 아니다. 인물 정체성, 동작 연속성, 프롬프트 복잡도, 재시도 비용, 검수량이 함께 흔들린다.

숫자는 이상을 발견하는 진단 신호다. 제작 법칙은 아니다.

## 세 단위를 먼저 분리한다

### CUT: 편집과 서사의 기능 단위

CUT은 관객에게 무엇을 보여주고 어떤 정보를 전달할지 정하는 단위다.

한 CUT은 다음 중 하나의 기능을 가질 수 있다.

- 새로운 공간을 소개한다.
- 화자를 전환한다.
- 행동의 원인이나 결과를 보여준다.
- 표정이나 반응을 강조한다.
- 시간의 경과를 표시한다.
- 다음 장면으로 리듬을 넘긴다.

CUT은 최종 편집에서 독립된 샷이 될 수도 있지만, 생성 단계부터 반드시 독립 영상이어야 하는 것은 아니다. 한 번 생성한 연속 영상 안에서 두세 개의 편집 CUT을 추출할 수도 있다.

### PANEL: 시각 상태를 고정하는 제작 안내 단위

PANEL은 스토리보드에서 특정 순간의 상태를 고정한다.

```txt
- 인물의 위치
- 카메라 거리와 방향
- 행동의 시작 또는 변화
- 공간 관계
- 표정과 시선
- 다음 상태로 넘어가기 위한 시각적 조건
```

패널은 영상 생성 횟수가 아니다. 한 영상 안의 움직임을 설명하기 위해 여러 패널이 필요할 수 있고, 반대로 단순한 대화나 반응은 한 장의 핵심 프레임만으로 충분할 수 있다.

### CLIP_GROUP: 한 번의 생성으로 연속 진행을 만드는 실행 단위

CLIP_GROUP은 영상 생성 도구에 한 번에 넘기는 실행 묶음이다.

좋은 CLIP_GROUP은 단지 CUT 번호가 연속된 묶음이 아니다. 같은 장소와 시간 안에서 하나의 물리적 진행을 만들 수 있는 CUT들의 집합이다.

```txt
CUT: 관객이 읽는 편집·서사 기능
PANEL: 제작자가 고정하는 시각 상태
CLIP_GROUP: 생성 모델이 수행하는 연속 실행
```

이 세 층을 분리하면 CUT 수, 이미지 수, 영상 생성 수가 서로 달라도 정상이라는 사실이 보인다.

## 가장 흔한 실패: CUT = PANEL = CLIP

첫 번째 실패는 모든 CUT에 이미지 한 장과 영상 한 개를 기계적으로 배정하는 것이다.

예를 들어 짧은 발화, 고개를 돌리는 반응, 손이 문고리에 닿는 순간을 각각 별도 장시간 영상으로 생성한다고 해보자. 편집상으로는 세 CUT일 수 있지만 물리적으로는 하나의 연속 행동이다.

```txt
CUT 21: 인물이 복도 끝을 본다.
CUT 22: 짧게 질문한다.
CUT 23: 문고리를 잡는다.
```

같은 장소, 같은 시간, 같은 인물, 같은 행동축이라면 한 번의 생성에서 시선 이동과 발화와 손동작을 연속 진행으로 만드는 편이 자연스럽다. 최종 편집에서 필요한 지점을 나누면 된다.

두 번째 실패는 반대로 너무 많이 묶는 것이다.

화자가 바뀌거나, 주요 인물의 기준 이미지가 달라지거나, 공간과 시간이 전환되는데도 생성 횟수를 줄이기 위해 하나의 그룹으로 밀어 넣으면 정체성 오염이 발생하기 쉽다. 한 인물의 얼굴이나 의상이 다른 사람에게 번지고, 대사의 주체가 섞이며, 공간 구조가 중간에 재설정된다.

복수 CUT을 묶는 행위가 문제가 아니다. 안전 경계를 넘어서 묶는 것이 문제다.

## 숫자 대신 묶는 이유를 본다

CLIP_GROUP을 만들 때는 다음 기준을 함께 본다.

### 1. 같은 장소인가

배경 구조와 주요 광원이 유지되는가? 문을 통과해 완전히 다른 공간으로 이동한다면 새 그룹이 더 안전할 수 있다.

### 2. 같은 시간인가

행동 사이에 생략된 시간이 없는가? 같은 방이라도 아침에서 밤으로 바뀌거나 사건 전후가 분명히 갈리면 연속 생성보다 분리가 낫다.

### 3. 같은 행동축인가

모든 CUT이 하나의 원인과 진행 방향을 공유하는가? 접근, 발견, 반응, 접촉처럼 물리적으로 이어지면 묶을 근거가 생긴다.

### 4. 연속적인 물리 변화가 있는가

시작 상태에서 끝 상태까지 중간 변화가 설명되는가? 단순히 “강도가 높아진다”가 아니라 누가 어디로 움직이고 무엇이 바뀌는지 말할 수 있어야 한다.

### 5. 멀티모달 생성의 이점이 있는가

여러 시각 가이드가 공간과 행동의 진행을 실제로 더 명확하게 만드는가? 단순 반응에 패널을 과도하게 늘리면 정보가 아니라 충돌이 증가한다.

### 6. 정체성과 화자 경계가 안전한가

주요 인물, 화자, 의상 기준, 얼굴 기준이 중간에 바뀌지 않는가? 바뀐다면 생성량 절감보다 분리를 우선한다.

묶는 이유를 한 문장으로 설명할 수 없다면, 그 그룹은 숫자 맞추기로 만들어졌을 가능성이 높다.

## 간단한 그룹핑 도식

```txt
[CUT A: 접근] ─┐
[CUT B: 발견] ─┼─ 같은 장소·시간·행동축 ─→ [CLIP_GROUP 1]
[CUT C: 반응] ─┘

[CUT D: 다른 화자의 대사]
          │
          └─ 화자·정체성 경계 ─────────→ [CLIP_GROUP 2]
```

이 도식에서 CUT A부터 C까지는 하나의 물리적 진행이다. CUT D는 번호상 바로 다음이지만 화자와 정체성 조건이 바뀌므로 별도 실행이 더 안전하다.

## 시각 가이드는 필요한 상태 수로 선택한다

패널 수를 품질 점수처럼 취급하면 또 다른 과잉 제작이 시작된다.

좋은 질문은 “몇 패널을 채워야 하는가?”가 아니라 “모델이 놓치면 안 되는 상태가 몇 개인가?”다.

### 한 장의 핵심 프레임

다음 상황에 적합하다.

- 정적인 소개 샷
- 짧은 표정 반응
- 공간과 인물이 이미 안정적으로 정의된 대화
- 움직임보다 구도와 분위기가 중요한 장면

### 소수의 다중 패널

다음과 같은 짧은 진행에 적합하다.

- 접근에서 접촉으로 이동
- 시선 전환과 발견
- 물체가 열리고 내부가 드러남
- 인물 위치와 카메라 상태가 두세 번 바뀜

### 액션 보조 시퀀스

고밀도 패널 시트는 복잡한 다단계 동작에만 쓴다.

- 추격이나 격투
- 군중 또는 다수 주체의 동시 행동
- 붕괴와 충돌처럼 원인과 결과가 여러 단계인 장면
- 공간 기하가 계속 변하는 장면

이때도 패널을 각각 독립 하드컷으로 실행하지 않는다. 패널은 동작의 숨은 안무이며, 최종 영상에서는 몇 개의 연속 비트로 압축된다.

### 기존 가이드 재사용

장소나 인물 기준이 이미 검증되었다면 매 CUT마다 새 이미지를 만들 필요가 없다. 다만 재사용하는 가이드가 현재 그룹에서 실제로 호출되는지 확인해야 한다.

미사용 패널과 중복 호출은 문서상의 사소한 정리 문제가 아니다. 모델이 서로 다른 상태를 동시에 따르거나, 정작 필요한 상태를 받지 못하는 실행 오류가 된다.

## 제작 결과에 미치는 영향

단위 설계는 생성량 이상의 문제를 결정한다.

### 생성량

모든 CUT을 독립 생성하면 필요 이상으로 영상 수가 늘어난다. 반대로 과도한 그룹핑은 한 번의 실패가 더 많은 CUT을 함께 무효화한다.

### 실패 재시도 비용

짧고 단순한 그룹은 수정 범위가 작다. 너무 큰 그룹은 한 인물의 손동작 오류 때문에 전체 긴 영상을 다시 생성해야 할 수 있다.

### 정체성 오염

여러 화자와 기준 인물을 한 번에 넣으면 얼굴, 의상, 체형, 역할이 서로 섞일 가능성이 커진다.

### 프롬프트 복잡도

그룹 안의 예외가 많을수록 프롬프트는 길어지고 우선순위가 불명확해진다. 좋은 그룹은 설명이 짧아서가 아니라 내부 조건이 일관되어서 명확하다.

### QA 작업량

검수자는 CUT, 패널, 생성 결과의 대응 관계를 확인해야 한다. 단위가 섞이면 “이 패널이 어느 영상에서 쓰였는가”라는 기본 질문부터 다시 추적해야 한다.

## 실행 전 체크리스트

- 각 CUT의 장면 기능을 한 문장으로 적었는가?
- CUT을 묶는 이유를 장소, 시간, 행동축으로 설명할 수 있는가?
- 화자와 주요 인물의 정체성 경계를 넘지 않았는가?
- 각 패널이 실제 실행에서 호출되는가?
- 같은 가이드가 불필요하게 중복 호출되지 않는가?
- 패널 수가 필요한 시각 상태보다 많거나 적지 않은가?
- 복잡한 동작만 액션 보조 시퀀스를 사용하는가?
- 생성 모델에 필요한 장면 정보와 관리용 식별자를 분리했는가?
- 한 번 실패했을 때 다시 만들어야 하는 범위가 합리적인가?
- 최종 편집에서 한 생성물을 여러 CUT으로 나눌 가능성을 고려했는가?

## 결론

CUT은 이야기를 편집하는 단위다. PANEL은 시각 상태를 안내하는 단위다. CLIP_GROUP은 연속 행동을 생성하는 단위다.

세 단위를 억지로 같은 수로 맞출 이유는 없다.

제작 수치를 보는 일은 중요하다. 특정 프로젝트에서 독립 클립이 지나치게 많거나, 사용되지 않는 패널이 반복되거나, 하나의 그룹이 여러 정체성 경계를 넘는다면 숫자는 분명 경고를 준다.

하지만 경고를 법칙으로 바꾸면 안 된다.

**Count is a diagnostic, not a production law.**
