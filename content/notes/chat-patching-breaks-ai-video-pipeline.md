# 채팅창 패치가 AI 영상 제작 파이프라인을 다시 무너뜨리는 이유

## 요약

AI 영상 제작 파이프라인에서 긴 제작 문서를 다룰 때, 가장 위험한 순간은 “수정 요청” 이후에 온다.

새로 발견한 문제를 고치기 위해 채팅창에서 전체 문서를 다시 출력하면, 방금 요청한 문제는 고쳐질 수 있다. 하지만 동시에 이전 버전에서 정상적으로 작동하던 구조가 다시 무너질 수 있다.

> 긴 제작 문서는 채팅창에서 계속 다시 생성할수록 불안정해진다.  
> 어느 부분을 바꾸었는지 추적할 수 있는 로컬 파일 기반 패치 방식이 필요하다.

## 문제가 된 방식

초기에는 긴 제작 문서를 채팅창에서 직접 수정했다.

```txt
1. 제작 문서를 만든다.
2. 오류를 발견한다.
3. 채팅창에 수정 요청을 한다.
4. 전체 문서 또는 큰 섹션을 다시 받는다.
5. 다시 검수한다.
```

처음에는 이 방식이 빠르게 느껴진다.

하지만 문서가 길어지고 규칙이 많아질수록 문제가 반복된다.

```txt
- 새로 요청한 문제는 고쳐진다.
- 이전에 정상 작동하던 규칙이 빠진다.
- 특정 패치에만 집중하다가 전체 구조가 흔들린다.
- 사람이 다시 처음부터 검수해야 한다.
- 수정 횟수가 늘수록 문서 신뢰도가 낮아진다.
```

결국 제작자는 “수정”을 하는 것이 아니라, 매번 새로운 불안정한 버전을 다시 검수하게 된다.

## 왜 채팅창 패치가 위험한가

채팅창은 대화와 생성에는 강하지만, 긴 파일의 변경 범위를 안정적으로 추적하는 작업에는 약하다.

특히 AI 영상 제작 문서에는 다음 정보가 동시에 들어간다.

```txt
- 컷 구조
- 레퍼런스 이미지
- 스토리보드 패널
- 영상 생성 프롬프트
- 대사 블록
- 시간 배분
- 캐릭터/장소/소품 alias
- 금지 문법
- 글자 수 제한
- 실행 도구별 입력 규칙
```

이런 문서에서 하나의 오류를 고치려면, 해당 오류만 고치고 나머지 구조는 유지해야 한다.

하지만 채팅창에서 문서를 다시 생성하면 “수정한 부분”과 “그대로 유지된 부분”을 명확히 분리하기 어렵다.

## 로컬 파일 기반 방식으로 바꾼 이유

해결 방향은 단순했다.

문서를 계속 다시 생성하지 말고, 파일로 고정한 뒤 변경 범위를 관리하는 것이다.

```txt
1. 원본 파일을 저장한다.
2. 원본은 직접 수정하지 않는다.
3. 복사본을 만든다.
4. 복사본에서만 검수와 패치를 진행한다.
5. 변경 요약을 만든다.
6. 필요한 경우 실행용 표 파일로 변환한다.
7. 검토 후 복사본을 공식본으로 승격한다.
```

이 방식의 핵심은 “더 똑똑한 프롬프트”가 아니다.

핵심은 **원본 보존과 변경 범위 통제**다.

## 로컬 제작 관리자가 맡을 수 있는 일

VS Code 안의 코딩 에이전트는 단순한 조언자가 아니라, 로컬 파일을 읽고 정리하고 수정할 수 있는 작업자로 사용할 수 있다.

AI 영상 제작 파이프라인에서는 다음 역할이 유용하다.

```txt
- 원본 파일 보존
- 복사본 생성
- 규칙 위반 감사
- 반복 문구 압축
- alias 규칙 검사
- 실행 프롬프트의 금지 문법 탐지
- 특정 위치에만 패치 적용
- 변경 요약 작성
- Markdown을 XLSX 같은 실행용 파일로 변환
```

이 역할은 창작자를 대체하지 않는다.

대신 제작 문서가 무너지는 것을 막는 “무결성 편집자”에 가깝다.

## 맡기면 안 되는 일

반대로 로컬 파일 기반 에이전트에게 바로 맡기면 위험한 영역도 있다.

```txt
- 대사 재작성
- 장면 의미 변경
- 컷 순서 변경
- 캐릭터 감정선 재해석
- 새로운 에셋 창작
- 시청자 보상 구조 판단
- 에피소드 전체 방향 결정
```

이런 작업은 단순한 파일 수정이 아니라 창작 판단이다.

## 역할 분리

현재 기준에서 가장 안정적인 역할 분리는 다음과 같다.

```txt
창작/전략 대화:
- 에피소드 방향
- 시청자 보상
- 대사 감각
- 장르 톤
- 세계관 판단
- 공개/비공개 경계

로컬 파일 기반 에이전트:
- 원본 보존
- 복사본 패치
- 규칙 검사
- 변경 요약
- 실행 파일 변환
- 반복 오류 자동 탐지

제작자:
- 최종 승인
- 실제 생성 결과 검수
- 업로드 판단
```

AI 영상 제작에서 중요한 것은 하나의 도구가 모든 것을 하는 것이 아니다.

각 도구가 잘하는 일을 정확히 나누는 것이다.

## 실무 체크리스트

긴 제작 문서를 수정하기 전에 아래를 확인한다.

```txt
1. 원본 파일을 직접 수정하고 있지 않은가?
2. 복사본에서만 패치하고 있는가?
3. 변경 범위를 확인할 수 있는가?
4. 새로 고친 부분 때문에 기존 규칙이 무너지지 않았는가?
5. 창작 판단과 기계적 패치를 분리했는가?
6. 실행용 파일로 변환할 때 원문이 누락되지 않았는가?
7. 최종 승인 전 변경 요약을 확인했는가?
```

## 최종 교훈

AI 영상 제작 파이프라인이 길어질수록 문제는 “AI가 더 똑똑한가”보다 “변경을 어떻게 통제하는가”에 가까워진다.

긴 문서를 채팅창에서 계속 다시 생성하는 방식은 빠르지만 불안정하다.

제작 문서가 실제 실행 도구로 이어져야 한다면, 필요한 것은 다음 세 가지다.

```txt
원본 보존
복사본 패치
변경 범위 확인
```

좋은 AI 제작 워크플로우는 더 많은 재생성이 아니라, 더 안전한 변경 관리에서 시작된다.
